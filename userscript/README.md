# QQ频道 原图 / 视频一键下载（Tampermonkey 脚本）

脚本**完全在浏览器内运行**：不需要 `qqdl` 终端、WebUI、Docker、Node 或任何本地代理/本地服务。唯一要求是浏览器能访问 `pd.qq.com` 和媒体 CDN；页面与文件都通过脚本管理器 API 获取。手机端（Kiwi、Firefox for Android 等支持油猴的浏览器）没有文件夹选择 API 时会自动进入浏览器默认下载模式。

在 QQ频道图文帖子页面右下角加一个「一键下载全部」按钮：

- 下载帖子里的**全部图片、GIF、视频（含视频封面）**，一个不漏；
- 图片走 CDN 的 `/o=` 原始规格，**不是**页面上的 `/b=` 缩略图；视频选最高码率；
- 下载后按文件头识别真实格式，默认文件名为
  `<频道ID>-<文章ID>-<序号>.<扩展名>`；
- 面板里可以**选择保存文件夹**，还可以填子目录（如 `每日偶玛`、`2026/10`）；
- 面板里可以修改**文件命名规则**，支持 `<channel_id>`、`<post_id>`、`<order>`、
  `<poster_id>`、`<poster_name>`、`<sub_channel_id>`、`<title>`、`<kind>`、
  `<ext>`、`<width>`、`<height>` 等变量，界面会直接列出提示；模板里写 `/`
  会创建子文件夹，例如 `<title>/<channel_id>-<post_id>-<order>`；
- 已授权过的文件夹会记住，之后点 FAB 可直接开始下载。
- 面板里可以填写“额外帖子链接”（每行一个），批量下载多个帖子的全部媒体。

## 安装

1. 浏览器安装 **Tampermonkey**（Chrome / Edge / Firefox 均可）。
2. 打开 Tampermonkey 管理面板 → 「添加新脚本」。
3. 用 `qqdl.user.js` 的全部内容替换编辑器内容，或直接把 `qqdl.user.js`
   拖进浏览器窗口按提示安装。
4. 保存后确认脚本已启用。

脚本匹配：

```
https://pd.qq.com/g/*/post/*
https://pd.qq.com/post/*
```

## 使用

1. 打开任意 QQ频道图文帖子，例如：
   `https://pd.qq.com/g/605695554027767602/post/B_51a2d56ad69b05001441152189397568750X60`
2. 等页面加载完，右下角出现 **「一键下载全部（N）」**。
3. 第一次用：点按钮 → 点「更换保存文件夹」→ 在系统目录选择器里选一个文件夹
   → 浏览器询问时点「允许编辑」。
4. 可填写子目录、修改「文件命名规则」（默认 `<channel_id>-<post_id>-<order>`；
   模板里写 `/` 会再创建子文件夹），
   勾选/取消「跳过已存在且大小一致的文件」，点「开始下载全部」。
5. 需要下载多个帖子时，在「额外帖子链接」里每行填一个链接，点「解析额外链接」，
   确认预览后再点「开始下载全部」；当前帖子和额外帖子会合并成一个批量任务。
6. 进度、成功/失败数量、每个文件的最终文件名和大小都会显示在面板里。

如果已经给过文件夹权限，再点 FAB 会**直接开始下载**；权限失效时会自动打开面板
让你重新授权。

## 保存路径说明

| 浏览器 | 自定义路径 | 说明 |
| --- | --- | --- |
| Chrome / Edge 86+ | ✅ 任意文件夹 | File System Access API，首次选择时授权一次 |
| Firefox | ⚠️ 仅浏览器默认下载目录 | 没有目录写入 API，自动回退为浏览器下载 |
| Safari | ⚠️ 仅浏览器默认下载目录 | 同上 |

- 选择文件夹后，脚本通过 `createWritable()` **直接写入你选的目录**，可以写中文、
  空格路径和子目录。
- 目录句柄保存在 IndexedDB，刷新页面后仍然有效；浏览器清理站点数据后需重选。
- 未选择文件夹时，脚本仍会用 `GM_xmlhttpRequest` 取回真实字节、按文件头确定扩展名，
  再交给浏览器下载。Chrome 可能询问「是否允许下载多个文件」，请选择允许。
- 浏览器安全模型不允许网页静默写任意绝对路径；「选择文件夹」就是授权动作，
  这是正常且必要的一步。

## 下载规则

1. 从页面 `__NUXT_DATA__`（Nuxt devalue）里找到当前帖子的 `feed`。
2. 图片：把 `picUrl` 的 `/b=`、`/c=`、`/m=`、`/s=`、`/0=` 替换成 `/o=`；
   已是 `/o=` 的 GIF 原样使用。
3. 视频：在 `vecVideoUrl` 里选 `videoRate` 最大的一路，同码率取更高
   `levelType`，回退 `playUrl`。
4. 图片与视频按 `display_index` 排序，序号相同图片在前，从 1 连续编号；
   视频封面也作为一张图片下载。
5. 下载完成后校验文件头，并对图片解码校验实际像素尺寸：只有实际尺寸
   **小于**页面标称尺寸才会判为失败；实际尺寸更大是正常的原图，直接保存。
   页面里的 `orig_size` 可能过期，不能作为失败依据（见下方常见问题）。
6. 页面数据里的 `imageMD5`、`orig_size` 实测都不可靠（部分原图与其不一致，
   但像素尺寸和真实字节完全吻合），因此脚本不拿它们做删除/失败依据。

## 常见问题

**右下角没有按钮？**
- 确认脚本已启用，且当前 URL 形如 `https://pd.qq.com/g/.../post/B_...`；
- 帖子页是 SPA，切换帖子后脚本会在 1 秒内重新解析；也可刷新页面；
- 帖子被删除、需要登录或没有访问权限时，页面本身就取不到 `feed`，脚本会提示
  「没找到帖子数据」。

**点「开始下载」提示没有权限？**
重新点「更换保存文件夹」，在系统弹窗里允许「编辑」；或者换一个普通文件夹
（不要选系统保护目录）。

**浏览器提示“下载多个文件”？**
未选择文件夹时的回退模式需要连续触发下载，Chrome 会询问一次，点允许即可。
推荐直接选择文件夹，走 File System Access 写入，不会触发多文件下载询问。

**下载失败/大小不一致？**
面板会显示失败原因；常见原因是网络中断、帖子媒体被删、或 CDN 临时 403。
再点一次开始即可重试；已成功的文件在勾选“跳过”时不会重复下载。

如果某个文件提示“页面元数据大小 51788 字节，实际文件 254166 字节”，这是
QQ频道帖子里的 `orig_size` 过期/写错，不是下载失败。脚本 1.2.1 起会继续保存
实际原图，并校验其像素尺寸不小于页面标称值。

**视频很大，会不会占内存？**
视频按字节流取回后写入；特别大的视频建议选择文件夹模式。若浏览器内存紧张，
可关闭其他标签页后重试。

## 开发与校验

```bash
node --check qqdl.user.js
```

脚本末尾把解析核心挂到 `module.exports`（仅 Node 测试时生效），浏览器里不会
暴露额外全局变量。仓库测试用的三个页面 fixture 不随脚本发布，脚本本身不含
任何测试桩或调试后门。

## 权限与隐私

- 只匹配 `pd.qq.com` 的帖子页，不会在其他网站运行；
- 只读取当前帖子公开页面里的媒体地址，不上传、不收集任何数据；
- `GM_xmlhttpRequest` 仅用于绕过图片 CDN 缺失的 CORS 头，直接读取公开原文件；
- 文件只写入你手动选择的文件夹；
- 不读取、不传输你的 QQ 登录 Cookie。
